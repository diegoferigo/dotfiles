# Encrypted dotfiles

Files below `secrets/home/` are armored age ciphertext. Their destination is
derived from the path:

```text
secrets/home/<path>.age -> ~/<path>
```

Initialize one shared identity through the installed dotfiles manager:

```bash
dotfiles secrets init
dotfiles git commit -m "Add encrypted age identity"
dotfiles git push
```

`init` generates the private identity in a temporary directory, asks `age` for
one passphrase, and stages:

```text
~/.config/dotfiles/age/identity.txt.age
~/.config/dotfiles/age/recipients.txt
```

The encrypted identity and public recipient are safe to track. Store a
high-entropy passphrase generated by `age` in a password manager. The encrypted
identity is automatically distributed by normal bootstrap and update, so a new
machine only needs the passphrase. A legacy plaintext identity at
`~/.config/dotfiles/age/identity.txt` remains supported for migration.

Encrypt and stage a file directly from `$HOME`:

```bash
dotfiles secrets encrypt ~/.ssh/config.d/rai.conf
dotfiles git diff --cached
dotfiles git commit -m "Add encrypted RAI SSH configuration"
dotfiles git push
```

The deterministic mapping writes
`secrets/home/.ssh/config.d/rai.conf.age` directly into the bare repository
index. No development clone or `$HOME/secrets` directory is needed. The
plaintext remains unchanged.

The command refuses unresolved repository conflicts and an existing staged
change to the same ciphertext. During a rebase, a conflict only on that
ciphertext can be resolved by selecting the intended plaintext and replacing
the unmergeable encrypted bytes:

```bash
dotfiles secrets encrypt --resolve ~/.ssh/config.d/rai.conf
dotfiles git rebase --continue
```

Resolve any other conflicted path first. A rejected command leaves the existing
index entry unchanged.

Apply or inspect encrypted files:

```bash
dotfiles secrets status
dotfiles secrets apply
```

Pass `--with-secrets` to combine explicit secret deployment with bootstrap or
update:

```bash
./bootstrap --with-secrets
dotfiles --update --with-secrets
```

`status` never decrypts content. `apply` decrypts and validates all sources
before changing files. If no plaintext identity is available, `age` prompts once
to unlock the tracked encrypted identity into a mode `0600` temporary file. The
temporary identity is removed before the command exits. Each target is deployed
atomically with mode `0600`, recorded immediately, and protected from local
overwrites unless `dotfiles secrets apply --force` is used. Deleting a ciphertext
removes its unchanged plaintext and restores any original backup.

Bootstrap and update only report that encrypted sources are available. They
never apply them automatically, so public-file operations cannot fail because of
a missing identity or malformed ciphertext. An interrupted explicit apply is
resumable.

Change the password-manager passphrase without touching any encrypted dotfile:

```bash
dotfiles secrets change-passphrase
dotfiles git commit -m "Change encrypted identity passphrase"
dotfiles git push
```

This decrypts the identity with the old passphrase, re-encrypts the same identity
with the new one, atomically replaces the wrapper, and stages it. Secret
ciphertexts do not change because their recipient is unchanged.

The shared identity minimizes maintenance but creates a shared blast radius. A
weak passphrase also permits offline guessing because the encrypted identity is
public. If the identity or an unlocked trusted machine is compromised:

1. Generate a replacement identity.
2. Replace the tracked encrypted identity and public recipient.
3. Re-encrypt every source.
4. Update every trusted machine.
