# Maintaining this skill

This skill is a set of instructions to follow, not a record of where each rule
came from. Every line must be actionable. Keep out:

- **Provenance**: who inspired a pattern, which person writes this way, which
  repo or PR it was observed in. A rule stands on its own, the source adds
  reading cost and can even mislead into imitating that person instead of Diego.
- **History**: what the rule used to be, why it was changed, when it was added.
- **Justification of the rule to the reader.** State the behaviour, and add the
  reason only when it changes how the rule is applied in an edge case.
- Anything an agent cannot act on while writing the artifact.

Examples are the exception: a short concrete sample of the desired output is
worth more than a paragraph describing it. Keep the sample, drop the attribution,
and anonymise repo-specific details unless they are the point.

Same rule for the reference files, and for the Contents list at the top of each
one, which must stay in sync when a section is added or renamed.
